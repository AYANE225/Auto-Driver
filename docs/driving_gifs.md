# 驾驶 GIF：来源、范围与复现

[在线展区](https://ayane225.github.io/Auto-Driver/#driving-gifs)提供五段可停止、可下载的 GIF。中英文 README 直接展示同一组动图。

| 片段 | 来源 | 仿真时间 | 记录与播放采样率 | 观察内容 |
|---|---|---|---|---|
| 前车急刹 | CARLA 0.9.16，实际 LiDAR | 4–11 s | 10 Hz | 前车 6 s 全制动，自车减速停车，速度与踏板变化 |
| 邻道切入 | 合成 LiDAR | 2–10 s | 5 Hz | 切入期间的状态与加减速变化，随后跟车 |
| 静态绕障 | 合成 LiDAR | 2–9 s | 5 Hz | 当前规划、已行驶轨迹、障碍真值与检测跟踪框 |
| 绿灯后连续行人横穿 | 合成 LiDAR | 8–19 s | 5 Hz | 绿灯后的低速让行，两名行人横穿与恢复巡航 |
| 感知超时与恢复 | 合成 LiDAR | 3–10 s | 5 Hz | 超时制动、保持停止、输入恢复后重新起步 |

这些片段根据已经记录的事件选择，保留片段内所有记录帧，**没有重新运行仿真、插值运动或平滑控制**。它们不是新增的五次实验，也不能用于估计成功率。原测试的完整结果仍是 26 次基础运行和 18 次单参数变化测试；参数变化包含默认参数重复，并非独立随机试验。

整组 GIF 共约 **11.27 MiB**：CARLA 为 9.63 MiB，四张合成场景各 0.23–0.55 MiB。网页按需加载，原始视频另行保留。

## 如何阅读

- 每张图统一为 1000 × 600，显示输入来源、原始采样率、仿真时间和单位。所有帧按 **1× 仿真时间**播放，不能由此推断计算实时性。
- 曲线只显示片段起点到当前时刻的记录值。采样点间用直线连接，未进行滤波；这不表示两个记录帧之间存在额外观测。加速度曲线和侧栏显示的是**指令**，不是加速度测量值。
- CARLA 用公开 MP4 的帧索引匹配 JSON：视频第 0 帧对应仿真约 0.1 s。导出时检查视频哈希、总帧数和逐帧时间；实际速度、参考速度、油门与制动取同一记录帧。
- 合成俯视图的 X/Y 使用相同比例，车辆和障碍按记录尺寸绘制。自车位姿对应后轴，绘车时使用记录的 `rear_to_center` 偏移到车身中心。绿色为自车与已行驶轨迹，蓝色为当前规划，橙色为障碍真值，紫色为检测跟踪框。障碍真值只用于图示，与规划输入分开标注。当前视窗之外的对象不显示。
- 黄色竖线表示报告中已发生的预设事件。状态、红绿灯与对象位置使用当前记录值；例如行人场景第一次记录绿灯是 10.2 s，而预设切换时刻是 10 s。
- 末帧按正常帧时长播放后，另加 **1.2 s**「节选结束」提示再循环。因此 GIF 总时长包含最后一个采样帧的持续时间和提示时间，不等于两个端点时间相减。

合成 LiDAR 没有光线遮挡模型。CARLA 前车急刹是限定路线的无路口低速仿真测试；GIF 不构成真实道路安全证明。切入片段中的短暂加速、再次减速与状态切换均保留，不能仅凭剪辑宣称所有场景的纵向控制都平稳。

## 数据与图像编码

[公开清单](assets/driving/gifs/index.json)包含每张 GIF 的 SHA-256、文件大小、每帧时长、源 JSON 哈希、源帧索引与仿真时间。CARLA 另有视频路径和哈希。`metrics` 与完整源报告相同，`metrics_scope` 为 `full_source_run`，**不是节选片段的重新评估**。

导出工具使用 Pillow 绘制，使用固定全局调色板减少颜色闪烁，并为曲线和状态保留专用颜色。合成 GIF 使用 gifsicle 无损压缩；CARLA 相机区域额外采用 `--lossy=40` 颜色压缩，曲线、文字与数值区域从未进行该有损处理。相机已按比例缩小以适合版面；原始公开 MP4 仍在[完整视频区](https://ayane225.github.io/Auto-Driver/#carla-driving)。编码不增删运动帧、不改变时序或指令值。

网页默认只加载 JPG 预览，点击后才加载 GIF；同一时刻播放一张，停止、离开画面或切到后台会恢复静态预览。关闭 JavaScript 时仍可通过链接打开或下载 GIF。GitHub README 的 GIF 自动播放由 GitHub 和浏览器控制。

## 复现

需要 Pillow、ffmpeg；gifsicle 用于压缩。发布时使用 Pillow 12.0.0、ffmpeg 6.1.1 和 gifsicle 1.94；清单保留版本、工具与字体哈希。不同依赖或字体版本可能改变编码字节，但源帧与时序应保持一致。

```bash
pip install pillow==12.0.0
# Ubuntu: sudo apt install ffmpeg gifsicle fonts-noto-cjk
python tools/export_driving_gifs.py \
  --out outputs/driving-gifs-new \
  --gifsicle /usr/bin/gifsicle --camera-lossy 40
```

输出目录必须为新目录。不传 `--gifsicle` 时也可导出，文件会更大；默认不启用相机有损压缩。字体路径可用 `--font` 和 `--bold-font` 指定。

工具只读取仓库内已公开的 JSON 和 MP4，不需要 CARLA 服务、原始采集目录或 GPU。输出 GIF、JPG、`index.json`，以及供人工检查的四帧联系表。发布时仅复制 GIF、预览 JPG 和 `index.json` 至 `docs/assets/driving/gifs/`，联系表保留在输出目录。

导出过程检查连续采样间隔、相机同步、曲线值不超出坐标轴及最终 GIF 逐帧时长。网站回归检查五张资产及源文件哈希、来源时间与指标、按需加载、播放与停止。修改导出脚本后，应重新生成整组资产以更新清单中的工具哈希。

本次还检查了编码后的起始、中间、末尾与循环提示帧，以及桌面和 390 px 手机布局。三套现有浏览器回归、回放时间对齐检查和 Ruff 通过；手动浏览器检查覆盖键盘播放、离屏停止、减少动态效果设置下默认静止，以及 GIF 加载失败后恢复预览。
